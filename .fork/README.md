# Fork tooling for JangMan-J/pi

This directory lives on the `fork/tooling` branch and is merged into `next`, the repository's default
branch, like every other fork branch. It keeps `next` in sync with `earendil-works/pi`, checks it, and
publishes each checked `next` commit as a release that machines install without building.

## Install pi from the fork

```sh
curl -fsSLO https://raw.githubusercontent.com/JangMan-J/pi/next/.fork/install-next.sh
chmod +x install-next.sh
./install-next.sh
```

`install-next.sh` downloads the latest `next-<commit>` release, verifies its SHA-256, unpacks it into
`~/.local/share/pi-fork/releases/<tag>/`, and switches the `current` link to it; `~/.local/bin/pi` links
through `current`, so the switch is one step and running sessions keep their files. It needs curl, tar,
sha256sum and Node 22.19 or newer, and no checkout. `--rollback` switches back to the previous release,
`--tag next-<commit>` installs a given release, `--reinstall` downloads again. `PI_INSTALL_ROOT`,
`PI_REPO` and `PI_BIN_DIR` override the defaults. A release is about 24 MB to download and 150 MB
installed, the same layout as pi's own installer.

## Release workflow

`.github/workflows/fork-sync.yml` runs daily, on every push to `next`, and on demand (Actions tab, "Sync
fork and release next", Run workflow; untick "push" for a dry run). On the schedule and on demand it runs
the full `sync.sh`: fast-forward `main` from upstream, rebase every branch, rebuild `next`, focused checks,
push. Then, when the `next` commit has no release yet, it builds, runs `npm run check` and
`check.sh focused`, packs with `pack-release.sh`, and publishes the release. It releases only when
`sync.sh --status` is clean (`next` is exactly the merge of the branches, `main` mirrors upstream). A
failed check or a rebase conflict publishes nothing. Commits and tags are signed by the `fork-sync bot` key (repo secret
`FORK_SYNC_GPG_KEY`). The five newest releases are kept.

## Develop the fork

```sh
curl -fsSLO https://raw.githubusercontent.com/JangMan-J/pi/next/.fork/install-tests.sh
chmod +x install-tests.sh
./install-tests.sh
```

`install-tests.sh` sets up a development checkout: it clones `~/pi` if missing (`PI_DIR` overrides),
installs dependencies and the pre-commit hook, builds, builds the pi-env daemon, aligns the branches with
origin, writes agent pointers, and runs `check.sh focused` (`--all` for the full suite, `--no-run` for setup
only). It also converts an older checkout that mounted the retired `fork-sync` branch at `.fork/`. It does
not install `pi`. `AGENTS.md` here is the procedure for changing the fork: branch ownership, the order of
operations, and recovery.

## Files

- `AGENTS.md`: the fork workflow for agents and people.
- `branches`: the branches merged into `next`, in merge order.
- `sync.sh`: `--status` reports main, every branch and next; `--align` resets them to origin when safe;
  `--rebuild-only` regenerates `next` from the current tips; the full mode tags tips, fast-forwards `main`,
  rebases every branch, rebuilds `next`, runs the focused checks and optionally pushes with
  `--force-with-lease`. It refuses to rebuild over commits made on `next`.
- `check.sh`: `focused` runs the tests the fork owns; `all` runs `npm run check` and `./test.sh`.
- `pack-release.sh`: packs a built checkout into `pi-next.tar.gz` for a release.
- `install-next.sh`: installs releases; `install-tests.sh`: sets up a development checkout.

## Rules

- Never commit directly to `next`; it is regenerated by `sync.sh`.
- Each fix lives on its owning branch (see `AGENTS.md`); `next` is only merges.
- Pre-sync tags are signed and pushed, so any previous state is recoverable from GitHub.
