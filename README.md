# Fork tooling for JangMan-J/pi

This branch (`fork-tooling`) holds the scripts that keep the fork's integration branch `next`
in sync with `earendil-works/pi`. It lives on its own branch so it survives re-clones; the
earlier copy was untracked and was lost with its working directory on 2026-10-24.

## Set up in a fresh clone

```sh
git remote add upstream https://github.com/earendil-works/pi.git
git fetch origin fork-tooling
git worktree add .fork fork-tooling
echo .fork >> .git/info/exclude
```

## Install scripts

`install-next.sh` clones or updates `~/pi` to `origin/next`, runs `npm ci --ignore-scripts` and
`npm run build:offline`, and links `~/.local/bin/pi` to the build (`--refresh-models` builds with a
model-data refresh; `PI_DIR`, `PI_BRANCH`, `PI_BIN_DIR` override the defaults). `install-tests.sh`
builds the pi-env daemon, sets up this worktree at `.fork/`, and runs `check.sh focused`
(`--all` for the full suite, `--no-run` for setup only). On a fresh machine:

```sh
curl -fsSLO https://raw.githubusercontent.com/JangMan-J/pi/fork-tooling/install-next.sh
curl -fsSLO https://raw.githubusercontent.com/JangMan-J/pi/fork-tooling/install-tests.sh
chmod +x install-next.sh install-tests.sh
./install-next.sh && ./install-tests.sh
```

## Files

- `install-next.sh`, `install-tests.sh`: see above.
- `branches`: the feature branches merged into `next`, in merge order.
- `sync.sh`: tag the current tips, fast-forward `main` to upstream, rebase every branch, rebuild
  `next`, run the focused checks, optionally push with `--force-with-lease`.
- `check.sh`: `focused` runs the provider payload tests the fork owns; `all` runs `npm run check`
  and `./test.sh`.

## Rules

- Never commit directly to `next`; it is regenerated by `sync.sh`.
- Each fix lives on its owning branch (see `branches`); `next` is only merges.
- Pre-sync tags are signed and pushed, so any previous state is recoverable from GitHub.
